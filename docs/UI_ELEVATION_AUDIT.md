# UI elevation audit — 2026-10-29

Scope: every one of the 37 client `.vue` files, both client stylesheet files, and their Vuetify elevation props. This is a source-level audit, **not** a rendered browser, phone, dark-map, or forced-colors visual acceptance test. CSS `box-shadow` is not synonymous with card depth: dots, selection/focus rings, and SOS/dispatch pulses deliberately remain separate.

| Surface | Files checked | Depth decision |
|---|---|---|
| Shell | `App.vue`, `styles/tailwind.css` | Sign-in (flat primary variant) has a small themed action shadow; tonal sign-out stays flat. Theme menus and logout modal keep Vuetify defaults; logo/status/spark halos are decorative. |
| Map | `components/map/MapCanvas.vue`, `PlaceSearchPanel.vue`, `HistoryPlaybackPanel.vue`, `LiveCompanionPanel.vue`, `ReverseAddressSheet.vue` | Map controls use a themed shadow with a forced-colors ring. Search, history and companion overlays use the floating tier over map tiles and the surface tier in tablet flow. In the phone's fullscreen dialogs their reused inner card borders/shadows/padding are flattened so only the modal surface has depth; selectable rows retain their own affordances. Reverse-address dialog retains native dialog depth. Peer dots retain their contrast ring. |
| Mission | `components/mission/MissionLivePanel.vue`, `MissionTimelinePanel.vue`, `MissionRatingPanel.vue` | Live/timeline content use surface depth; rating choices use their own focus/selection treatment, not another card shadow. |
| Sharing/settings | `components/sharing/ShareLists.vue`, `ShareDialog.vue`, `LiveBroadcastBar.vue`, `components/settings/DevicePriorityPanel.vue` | Lists and device cards use surface depth even with Vuetify `elevation="0"` (`!important` override required). Broadcast is level 2 standalone and level 0 inset into dashboard; the map uses a separate icon-only share control, not a broadcast card inside the companions dialog. Dialogs/chooser keep Vuetify modal depth. |
| SOS | `components/sos/SosRequestSheet.vue`, `SosCancellationDialog.vue`, `SosTriggerButton.vue` | Sheet and confirmation use native overlay depth. Emergency FAB keeps its distinct red glow and reduced-motion handling; no general card shadow on it. |
| Public/placeholders | `views/PlaceholderPage.vue`, `views/_public/PlaceholderView.vue`, `views/_auth/PlaceholderView.vue`, `views/_admin/PlaceholderView.vue`, `views/_user/PlaceholderView.vue` | Shared welcome card uses the featured tier; wrappers add no shadows. |
| Auth | `views/_auth/LoginView.vue`, `RegisterView.vue`, `ForgotPasswordView.vue`, `views/_user/CompleteSecurityQuestionsView.vue`, `styles/auth.css` | Gradient intro uses hero depth; form uses featured depth; enabled submit has action depth, disabled submit is flat. Decorative sparks and insets retain their own styling. |
| Admin | `views/_admin/AdminUsersView.vue`, `AdminCategoriesView.vue`, `AdminIncidentsView.vue`, `AdminDispatchView.vue` | Table and dispatch primary cards use the themed surface tier, 24px corners and a subtle semantic border. The mission timeline remains an inset outlined region rather than a second raised card; the selected SOS card floats only over the map and uses surface depth when columns stack. Alert/status pulses remain distinct and stop under reduced motion. |
| User dashboard & sharing | `views/_user/UserDashboardView.vue`, `UserDevicesView.vue`, `UserLocationSharesView.vue`, `UserMapView.vue` | Dashboard/device/share-list content uses surface depth. User map cards use floating depth over tiles and surface depth in tablet flow. The three full-screen phone map dialogs flatten inner card depth to avoid card-in-card chrome; nested dashboard broadcast is level 0. |
| User missions & history | `views/_user/UserMissionView.vue`, `UserProposalsView.vue`, `UserRescuerHistoryView.vue`, `UserSosHistoryView.vue` | Content panels use surface depth; gradient headers use hero depth; selectable rows use the lighter item tier with hover/selected/focus preserved. Mobile scrolling leaves room for row shadows. Emergency and status indicators retain their own glows. |

Original inventory at audit time (before the dispatch surface follow-up): 21 literal Vuetify elevation props (15 at level 0, 2 at level 2, 3 at level 3, 1 at level 4), 1 conditional prop, **zero** Tailwind `shadow-*` classes in templates. No universal `.v-card` shadow rule was introduced: that would elevate dialogs, inset widgets, outlined cards and disabled states incorrectly. Source-pinned tests cover the chosen roles; actual visual balance and CSS cascade should still be checked in a rendered light/dark browser at desktop and phone widths.
