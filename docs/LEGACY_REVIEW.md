# Legacy architecture review

The previous repository was a large multi-package system. The visible portions included a Fastify server with TypeScript, PostgreSQL and PostGIS, Socket.IO, OpenAPI tooling and roughly forty store and route registrations; a Vue, Vuetify, Tailwind, Vite, Pinia, VueUse and MapLibre client; an Ionic and Capacitor Android application; an independent offline MVT map server; twenty-one Drizzle migrations; and separate admin and map design trees. The review was intentionally partial before the clean rebuild, so this document records structural conclusions rather than claiming a complete line-by-line audit.

## Problems addressed

The old architecture duplicated concepts across packages: API groups, client stores, realtime rooms, map caches, theme definitions, status values and test fixtures. Runtime work was spread across a web server, a map server, a database server and several build toolchains. This made a local clean start expensive and made it difficult to prove that an SOS transition, a socket event and an administrator table were driven by one state machine.

The clean rebuild replaces that with one Node process, one SQLite schema, one declarative route table, one service layer, one WebSocket endpoint, one shared protocol module and one browser application. Pure geometry and state rules are centralized. Offline map tiles are deterministic SVG generated in-process rather than a separate MVT service. Static assets are generated by one script and precached by one service worker.

## What was retained

The canonical images, reference generators, icon inventory and theme files under `design/` were retained as the visual contract. The product remains right-to-left, keeps system/light/dark themes, preserves the mobile map as the primary surface, and keeps administrator concepts such as overview, dispatch, users, groups, reports, audit, alerts and settings. The SOS and mission workflows, press-and-hold talk, live location, history playback and saved places remain first-class features.

Stable demo identifiers were recreated in a compact catalog so deterministic tests can exercise registration, recovery, dispatch, sharing and mission completion. Hardcoded demo credentials remain outside production seeding. The old idea of durable events and audience-filtered catch-up was retained but simplified into one SQLite event table and one post-commit publisher.

## What was discarded

Framework-specific stores, plugin chains, separate package manifests, multiple lockfiles, ORM migrations, Docker and proxy files from the old deployment, old Python design tests and legacy documentation were removed. The clean branch stages those deletions while `HEAD` retains the old blobs, so a reviewer can inspect any previous file with `git show HEAD:<path>` without affecting the new implementation.

All old tests and manuals were replaced by new English documentation and a new Node test suite. The new tests cover pure rules, API contracts, authentication, security, realtime coordination, PTT binary frames, live location, hypothetical journeys, architecture boundaries and generated assets. This makes the rebuilt system verifiable from a clean checkout with one install and one check command.
