# بازطراحی صفحهٔ نقشه، مسیریابی و مأموریت — تصاویر مرجع

این پوشه شامل **تصاویر مرجع (reference mockups)** بازطراحی صفحهٔ `/_user/map` است.
تصاویر با ابزار اختصاصی خودمان رندر شده‌اند تا متن فارسی/RTL دقیق و نقشه در همهٔ
صفحه‌ها یکسان باشد (جزئیات در بخش «چطور ساخته شد»).

> مرحلهٔ فعلی: **مرحلهٔ ۱ — تولید تصاویر مرجع**. پیاده‌سازی Vue/TypeScript، ماشین حالت
> مأموریت، جداسازی کامپوننت‌ها و تست‌ها در مرحلهٔ بعد انجام می‌شود.

## ۲. تصمیم‌های طراحی کلیدی

1. **انتخاب‌گر چهاربخشی در بالای صفحه** (تاریخچه / مسیریابی / همراهان / مأموریت) با «مسیریابی»
   به‌عنوان پیش‌فرض؛ در مأموریت فعال سه بخش دیگر غیرفعال و با آیکن قفل مشخص می‌شوند. «همراهان»
   بخش مستقل است، نه زیرمجموعهٔ تاریخچه: سفر مشترک، موقعیت زنده و اشتراک‌گذاری اینجا زندگی
   می‌کند و سوابق در تاریخچه می‌ماند.
2. **جستجو در پایین صفحه** (۵۲–۵۸px ارتفاع، safe-area رعایت‌شده) تا با انگشت شست در دسترس باشد؛
   نوار جستجوی قدیمی و منوی پایین «جستجو/تاریخچه/همراهان» حذف می‌شود.
3. **نقشه عنصر اصلی** است: پنل‌ها حداکثر ۴۵٪ ارتفاع را می‌گیرند و همه به شکل
   Bottom Sheet با دستگیره و CTA در بالای ناحیهٔ امن نمایش داده می‌شوند.
4. **سلسله‌مراتب SOS**: دکمهٔ SOS از ناحیهٔ شست فاصله دارد، رنگ قرمز پر دارد و برای ارسال
   تأیید/نگه‌داشتن می‌خواهد. هیچ عنصر دیگری از قرمز پر استفاده نمی‌کند.
5. **رنگ فقط حامل معنا نیست**: هر وضعیت رنگ + آیکن + متن دارد (مثلاً «ترافیک روان» چیپ سبز
   با آیکن و متن).
6. **راهنمای مسیر heading-up**: در سفر فعال نقشه می‌چرخد تا مسیر پیش‌رو به بالای صفحه بیاید.
7. **اعداد فارسی ولی LTR** در جمله‌های RTL (مثل ۱٫۲ کیلومتر، ۹:۵۰) تا شمارش و ساعت درست خوانده شود.
8. **قاعدهٔ چیدمان RTL در بدوی‌ها**: هر عنصری که آیکن و متن را کنار هم می‌گذارد، محتوا را از
   لبهٔ راست می‌چیند (آیکن راهنما راست، برچسب چپ آن)؛ این قاعده در `prims.chip()`،
   `prims.button()`، `prims.segmented()`، `ui.quick_chips()` و `ui.metric_tiles()` پیاده شده
   است و هر بدوی جدید هم باید همان را رعایت کند.
9. **یک شهر ثابت برای همهٔ تصاویر** (خیابان ولیعصر/شریعتی، رودخانه، پارک ملت) تا مجموعه
   تصاویر مثل یک محصول واقعی خوانده شود، نه ۴۰ صفحهٔ بی‌ارتباط.
10. **همسفر = نشانگر گرد با حلقهٔ تازگی**: حلقهٔ فیروزه‌ای (تازه، زیر ۴۵ ثانیه)، کهربایی (قدیمی)،
    خاکستری خط‌چین (هرگز موقعیتی نرسیده). رنگ حلقه هرگز با رنگ مسیر اشتباه نمی‌شود و همیشه یک
    نوار راهنمای سه‌کلیدی زیر کنترل بالایی آن را توضیح می‌دهد.
11. **ردّ طی‌شده تنها عنصر نیمه‌شفاف نقشه است**؛ هر همسفر ردّ خودش را دارد و «مسیر مشترک»
    خط‌چین و کم‌رنگ زیر همه می‌ماند. برای اینکه برچسب‌ها روی هم نیفتند، دوربین به امتداد مسیر
    هم‌سفرها می‌چرخد (`heading_up`) و جای هر نشانگر با assert کنترل می‌شود.
12. **صحبت یک‌به‌یک با فشار-و-نگه‌داشتن**: هیچ مودال و هیچ تماس گروهی. حلقهٔ کهربایی، بَج
    میکروفن و یک خط پالس بین دو نشانگر، حالت «در حال صحبت» را می‌سازند؛ شیت پایین فقط می‌گوید
    با چه کسی و چند ثانیه.
13. **همراهان و اشتراک موقعیت دو بخش جدا هستند**: افزودن همسفر → سفر مشترک؛ اشتراک موقعیت →
    گیرنده‌ای که لزوماً همسفر نیست، نامحدود یا محدود به زمان (کشویی/چیپ مدت)، و همیشه قابل قطع.
14. **پایان سفر یک تصمیم است**: سفر عادی با «ذخیره در تاریخچه» یا «بدون ذخیره» بسته می‌شود؛
    برای مأموریت‌های امداد این انتخاب وجود ندارد و همیشه در سوابق می‌ماند.
15. **تاریخچه کیفیت «ثبت» دارد، نه فقط فهرست**: جزئیات سفر مسیر پیشنهادی، مسیر طی‌شده، نقطهٔ
    انحراف، تکهٔ اشتباه و مسیر جایگزین را با هم نشان می‌دهد و سیر سفر (شروع / انحراف / مسیر
    جدید / رسیدن) با ساعت روی همان صفحه می‌آید.

## ۳. چطور ساخته شد (بازتولیدپذیر)

تصاویر با یک رِندرر کوچک پایتون در `_generator/` ساخته شده‌اند، نه با هوش مصنوعی تصویری.
دلیل: مدل‌های تصویری متن فارسی را خراب می‌کنند و هر تصویر نقشه/رنگ متفاوتی می‌سازند؛
برای بازبینی UI و پیاده‌سازی بعدی به تصاویر دقیق و قابل‌تکرار نیاز داریم.

```
_generator/
├── render.py              # نقطهٔ ورود: ساخت همه یا بخشی از تصاویر
├── bb/                    # جعبه‌ابزار طراحی
│   ├── theme.py           # توکن‌های رنگ/تایپ/فاصله (هم‌راستا با styles/tokens.ts پروژه)
│   ├── text.py            # شکل‌دهی فارسی + RTL + شکستن خط
│   ├── icons.py           # آیکن‌های MDI (همان فونت پروژه)
│   ├── prims.py           # بدوی‌های UI (کارت، دکمه، چیپ، شیت، اسکریم…)
│   ├── map.py             # رِندرر نقشهٔ برداری + مسیر + نشانگرها
│   ├── ui.py              # کامپوننت‌های سطح صفحه (chrome، بنر مانور، متریک…)
│   └── scenario.py        # دادهٔ ثابت سناریو (مبدأ/مقصد/مسیرها)
├── screens/               # تعریف هر تصویر (design_system, history, nav, mission, companions)
└── assets/                # فونت وزیرمتن + فونت آیکن MDI (برای رندر مستقل)
```

اجرا:

```bash
cd design/map-page/_generator
python3 -m venv .venv && . .venv/bin/activate
pip install pillow arabic-reshaper python-bidi
python render.py                 # همهٔ تصاویر
python render.py navigation      # فقط یک بخش (history | navigation | mission | companions | design-system)
python render.py 09-navigation-active --sheet
```

خروجی‌ها تکرارپذیرند (بدون تصادف در چیدمان)؛ هر تغییری در توکن‌ها همهٔ تصاویر را هم‌زمان
به‌روز می‌کند. `_preview-*.png` در پوشهٔ `_generator/` فقط برای مرور سریع کل بخش است و
بخشی از خروجی رسمی نیست.

| اشتراک موقعیت | `components/sharing/ShareDialog.vue`, `ShareLists.vue`, `views/_user/UserLocationSharesView.vue`, `api/location.ts` — مدل موجود `timed | permanent` است و همان چیزی است که تصویر `06` نشان می‌دهد |
| اشتراک تاریخچه | مجوز (grant) + نقاط سقف‌دار روی همان API؛ در تصاویر یک بازهٔ از/تا با پیش‌نمایش تعداد سفر و نقطه آمده |
| پایان سفر با انتخاب ذخیره | در کد فعلی سفر بی‌قید ذخیره می‌شود؛ نیازمند تصمیم صریح کاربر + قاعدهٔ «مأموریت همیشه ذخیره» |
| مأموریت فعال | `UserMissionView.vue` + `use-mission-desk.ts` (وضعیت‌های pending/on_the_way/arrived/in_progress) |
| پیشنهاد مأموریت | `stores/proposal-inbox.ts`, `ProposalInboxContent.vue` |
| وضعیت آمادگی | endpoint اختصاصی در کد فعلی دیده نشد؛ نیازمند API جدید (مستند در مرحلهٔ بعد) |
| درخواست پشتیبانی/لیدر | زیرساخت فعلی فقط mission + presence دارد؛ نیازمند API مأموریت چند‌نفره |
| SOS | `SosTriggerButton.vue`, `SosRequestSheet.vue`, `use-sos-request.ts` |

نکته‌های وابستگی backend که در مرحلهٔ پیاده‌سازی باید تأیید یا ساخته شوند (طبق متن پرامپت،
نباید به‌عنوان عملکرد واقعی جا زده شوند):

- وضعیت «آمادهٔ دریافت مأموریت» (toggle) — endpoint خواندن/نوشتن برای امدادگر.
- درخواست پشتیبانی و مدل تیم چند‌نفره (لیدر/اعضا) و اعلان لحظه‌ای پذیرش نیرو.
- ثبت گزارش کوتاه پایان/لغو مأموریت.
- دسترسی ادمین/لیدر به تاریخچهٔ موقعیت مأموران در بازهٔ مأموریت.
- **فشار-و-نگه‌دار برای صحبت (push-to-talk) یک‌به‌یک** با هر عضو اعزام‌شده: کانال صوتی
  نقطه‌به‌نقطه روی WebRTC + signalling لحظه‌ای و presence جدا برای هر عضو (حالت «در حال صحبت»
  با زمان‌شمار). **تماس گروهی وجود ندارد و ساخته نمی‌شود**؛ فقط صحبت دونفره با هر عضو،
  مثل بی‌سیم واقعی (`mission/14-team-leader-dashboard.png`).

## ۵. وضعیت بازبینی

هر ۵۷ تصویر رندر شده و بازبینی چشمی شده‌اند. مواردی که در بازبینی اصلاح شد:

- **انتخاب‌گر سه‌بخشی** حالا واقعاً RTL است: «تاریخچه» در سمت راست و «مأموریت» در سمت چپ؛
  نشان تعداد پیشنهادها روی گوشهٔ همان قرص فعال می‌نشیند.
- **پس‌زمینهٔ مودال‌ها** (SOS، تأیید مأموریت، لغو سفر، جستجو) با لایهٔ نیمه‌شفاف ترکیب می‌شود،
  نه یک مستطیل تیرهٔ یکدست؛ نقشه زیر آن خوانده می‌شود.
- **درصد/متن‌های سرریز** در کارت‌های تاریخچه و صفحهٔ خطا اصلاح شد (متن دو‌خطی داخل کارت،
  بدون بریدگی).
- **شیت پیشنهاد مأموریت** به شیت پایین‌چسب کامل تبدیل شد؛ شمارهٔ پیشنهاد، نقطه‌های صفحه‌بندی
  و راهنمای کشیدن همه داخل شیت هستند.
- **داشبورد تیم** و **اعلان پذیرش نیرو** فشرده و مرتب شدند؛ کلید اعلان صوتی به شیت اضافه شد.
- **بازبینی RTL سراسری** روی همهٔ ۵۷ تصویر: هر کنترل ترکیبی (چیپ، دکمه، انتخاب‌گر سه‌بخشی،
  چیپ میان‌بر، کاشی متریک، قرص فیلتر) از لبهٔ راست چیده می‌شود — آیکنِ راهنما سمت راست و متن
  سمت چپ آن. استپرها `+` را روی لبهٔ راست می‌گذارند.
- **بریدگی متن** در کارت سفر (خط جداکننده روی آدرس) و در ردیف همراهان (دُم حروف فارسی)
  برطرف شد؛ ردیف متریک‌های خلاصهٔ ماه حالا از راست به چپ مرتب است.
- **برچسب خیابان‌ها** دیگر زیر نشانگر POI نمی‌رود؛ در صورت تصادم، برچسب در امتداد خیابان
  جابه‌جا می‌شود (نه حذف).
- **حالت خالی تاریخچه** کوتاه و متعادل شد؛ شمارندهٔ «۰» که شبیه یک نقطه دیده می‌شد حذف شد.
- **چندمقصدی و بازچینش** با `fit_camera` قاب‌بندی می‌شوند تا مسیر از کنترل‌های بالای صفحه
  رد نشود.
- **قفل شدن دو بخش دیگر** در تمام دوازده تصویر «مأموریت فعال» واقعاً رندر می‌شود
  (آیکن قفل + رنگ غیرفعال، با کنتراست کافی) — پیش‌تر فقط در متن گفته شده بود.

### بازبینی دور «همراهان + تاریخچه» (۱۴۰۵/۰۸/۱۳)

- **انتخاب‌گر چهاربخشی** به همهٔ ۵۷ تصویر اعمال شد؛ آیکن و فاصلهٔ بخش‌ها برای ۴ برچسب بازتنظیم
  شد تا در ۸۹px هر بخش هم بخوانا باشد و هم قابل لمس.
- **چیدمان RTL انتخاب‌گرهای کوچک** اصلاح شد: پیش‌تر `segmented_small` گزینهٔ اول را چپ می‌گذاشت
  («مسیرهای من» سمت چپ «همراهان»)؛ حالا گزینهٔ اول سمت راست است و در هر ۷ تصویر تاریخچه دیده می‌شود.
- **دوربین سفر مشترک** سه بار بازنویسی شد: قاب‌گرفتن کل مسیر، سه نشانگر را در یک گوشه جمع می‌کرد؛
  برش مسیر هم کافی نبود چون این خیابان افقی است و سه نفر کنار هم می‌افتادند. راه‌حل نهایی:
  چرخش به امتداد مسیر (`heading_up`) + حل کردن zoom و مرکز از خودِ تصویر، با دو assert
  (همه داخل کادر امن، فاصلهٔ هر دو نشانگر ≥ ۴۶px).
- **هم‌خوانی متن و نقشه**: جمله‌های شیت («۱۹۰ متر جلوتر») با t هر همسفر روی مسیر محاسبه شدند؛
  پیش‌تر مریم ۲۰۰ متر «جلوتر» بود اما روی نقشه ۳۷۰ متر عقب‌تر.
- **برچسب‌های نقشه**: قرص نام هر نشانگر در لبهٔ صفحه clamp می‌شود و برچسب‌های بلند («… · در حال
  صحبت») حذف شدند؛ همین باعث می‌شد نام سعید کامل از کادر بیرون بیفتد.
- **ریز‌ایرادهای شیت‌ها**: مقدار ردیف‌های وضعیت به‌جای `align="right"` از چپ چیده شد (سرریز به
  بیرون صفحه)، شیت وضعیت و آفلاین از سیستم‌بار سرریز نمی‌کنند (assert ارتفاع)، چیپ‌های نام و
  چیپ‌های مدت با اندازهٔ واقعی متن چیده شدند.
- **اشتراک تاریخچه**: فیلد «از تاریخ» به سمت راست رفت و «تا تاریخ» به چپ (ترتیب RTL) و بازه دیگر
  معکوس نیست؛ پیش‌فرض‌ها هم راست‌به‌چپ و «سفارشی» انتخاب‌شده تا با بازهٔ دست‌چین‌شده هم‌خوان باشد.
- **پایان سفر** حالا دو دکمهٔ «ذخیره در تاریخچه» / «بدون ذخیره» با پیامد صریح دارد و یادآوری
  می‌کند که مأموریت‌های امداد همیشه ثبت می‌شوند (تصویر `mission/17` هم همان را می‌گوید).
- **جزئیات سفر تاریخی** از سه قدم عمومی به یک مقایسهٔ واقعی تبدیل شد: مسیر پیشنهادی (خط‌چین)،
  مسیر طی‌شده (توپر)، تکهٔ اشتباه (کهربایی خط‌چین)، مسیر جایگزین (آبی) + نقطهٔ انحراف + راهنمای
  چهارکلیدی روی نقشه.
- **صفحهٔ پایان مأموریت**: عنوان و تیک از روی خیابان‌ها برداشته و روی کارت خودش نشست؛ یک نوار
  زمانی «درخواست → رسیدن → پایان» هم اضافه شد.
