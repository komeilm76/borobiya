# Client design-token migration — Batch 2: shared application shell

## Scope and change

- Introduced theme-aware `shellColors` plus theme-independent `shellTypography`, `shellLayout` and `shellRadii` in `packages/client/src/styles/tokens.ts`. The same global stylesheet installed by `main.ts` now exports their `--bb-shell-*` variables for both themes. Values remain editable in **one configuration file**.
- Migrated the shared global styles in `styles/tailwind.css`: app bar, brand, navigation ink, hero and workspace placeholder/welcome surface, status, notes, footer, map action shape and tonal error alert. Also migrated account-profile menu type/radii, shell network/proposal action radii and the admin SOS toast type/radius. Unchanged existing `--bb-*` and Vuetify colors/shadows still derive from `tokens.ts`.
- This is a **selective, reviewed shell batch**, not all-app completion. 320px minimum, 44/48px touch targets, responsive cutoffs, safe-area calculations, measured map sheet clearances, functional status state and browser `CanvasText` forced-colors values remain local. Other isolated shell spacing/type, map proposal/sidebar layouts and page-specific presentation will be reviewed in the later batches/final audit. The inventory is in `../../../docs/CLIENT_STYLE_TOKEN_MIGRATION.md`.

## Visual and behavior validation

- Fixture-backed Chromium visited `/_user/settings` at 390×1117, 645×860 and 1007×630 in both themes. For the **baseline** capture, the previous committed global CSS (`git show HEAD:packages/client/src/styles/tailwind.css`, captured before this batch was committed) was overlaid on the same app to isolate the shell CSS change. Corresponding `baseline-light-*`/`after-light-*` and `dark-baseline-*`/`dark-after-*` images differ by **0 pixels at all six sizes** (ImageMagick `compare -metric AE`). Computed foreground, background, border, shadow, radius, font size and element geometry also match for topbar, brand, navigation, main, hero, welcome card/symbol, status, note and footer. No document overflow or page errors were observed. These are **local fixture captures, not genuine user-session screenshots**.
- On the device page, six separately captured images of the same authenticated fixture (`device-after-light-*`, `dark-device-after-*`) were compared with Batch 1's corresponding `../batch-1/after-light-*` and `../batch-1/dark-after-*`: **0 differing pixels at all six sizes** on the final re-capture. The app shell, session rows and widths stayed unchanged. The plain `after-light-*`/`dark-after-*` names in this directory show the placeholder route.
- Profile-menu-open captures (`menu-light-*`, `dark-menu-*`) at phone and desktop widths show the account menu in each theme. Computed theme-row radius was **12px** and type size **13.6px** with either palette; these use an intercepted-auth fixture too.
- A live-browser variable override on the phone (`--bb-shell-heroInk`, `--bb-shell-font-heroTitlePhone`, `--bb-shell-radius-symbol`) changed computed hero ink to `rgb(18, 52, 86)`, font to `40px` and radius to `8px`, demonstrating that editing the configuration affects rendered styles. The default values were restored after the probe.
- Source-pinned regression tests assert every shell role is emitted in both themes, no hardcoded color survives in `tailwind.css` outside intentional pre-mount fallbacks, theme-specific contrast for nav/brand/status/error and continued fixed map action shape. Shared error alert tests remain in place; no live network-error or revoke flow was exercised.
