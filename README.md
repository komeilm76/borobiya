# Borobiya

Borobiya is a clean rebuild of the offline location, emergency request and dispatch platform. It provides a right-to-left mobile map experience, live location sharing, one-to-one push-to-talk, SOS creation and dispatch, mission progress, history playback and a desktop operations console. The application has zero runtime dependencies: Node.js native HTTP, WebSockets, SQLite and TypeScript execution replace the earlier framework stack.

## First steps

1. Install Node.js 22.12 or newer and run `npm ci` to install the two development tools only.
2. Run `./boro setup` to copy `.env.example` when needed, generate self-hosted design assets and create the SQLite database.
3. Run `./boro dev` for a watch-mode development server, or `npm start` for a single foreground process.
4. Open `/_auth/login`. The administrator account uses `ADMIN_USERNAME` and `ADMIN_PASSWORD` from `.env`; demo accounts are seeded outside production.
5. Run `npm run check` before committing. It regenerates assets, typechecks server and browser sources, validates documentation and executes the full test suite.

## Repository layout

- `src/core` contains dependency-free HTTP, validation, configuration, rate limiting, static file and WebSocket primitives.
- `src/domain` contains pure geometry, state machines, catalogs and deterministic offline vector tiles.
- `src/db` contains one SQLite schema, a typed repository and the transaction/event boundary.
- `src/services` contains authentication, profiles, live location, SOS, missions, talk floor control, administration and realtime use cases.
- `src/routes` declares every endpoint and its request schema; `src/app.ts` wires the server.
- `public` contains the browser application, generated fonts and icons, stylesheet, manifest and service worker.
- `design` is the canonical visual contract. Images and reference generators are read-only inputs; do not alter them without an explicit design revision.
- `docs` contains practical English manuals and runbooks. `tests` contains the new automated suite.

## Runtime model

A single Node process serves the SPA, JSON API, offline SVG tiles and native WebSocket endpoint. Every state-changing use case commits a SQLite transaction and durable event rows, then publishes those events to connected clients after commit. The browser keeps one authenticated WebSocket, reconnects with one-use tickets and catches up through the durable event cursor. Audio is ephemeral 16 kHz PCM16 over binary frames and is never recorded or stored.

Static assets are generated by `scripts/build-assets.mjs` and precached by a versioned service worker. Offline vector tiles use a separate bounded cache. Private API responses are never cached by the service worker.

## Important commands

- `npm run assets` — regenerate fonts, icon CSS, logos and the cache manifest.
- `npm run typecheck` and `npm run typecheck:client` — validate server/test and browser TypeScript sources.
- `npm test` — run all new tests with the Node test runner.
- `npm run test:api`, `npm run test:sockets`, `npm run test:journeys` — run focused suites.
- `./boro doctor` — verify runtime and repository prerequisites.
- `./boro verify` — run diagnostics plus the full check pipeline.
- `./boro deploy:check` — validate production environment and generated assets.

Read `docs/README.md` for the documentation index. The canonical visual contract is summarized in `design/README.md`.
